# Практическая работа №1
## Техническое задание. Тема 2: Планировщик обслуживания электрооборудования

### Назначение проекта
Проект предназначен для планирования обслуживания электрооборудования. Система должна хранить оборудование, создавать задачи осмотра и ремонта, а также отслеживать текущий статус работ.

### Описание предметной области
На производстве оборудование требует планового обслуживания. Если работы вести без единой системы, сложно контролировать сроки, приоритеты и ответственных. Приложение позволяет свести эти данные в один интерфейс.

### Пользователи системы
- Техник - создаёт задачи обслуживания.
- Инженер - контролирует статус выполнения.
- Ответственный по участку - добавляет оборудование и ведёт карточки объектов.

### Функциональные требования
- Добавление оборудования.
- Создание задачи обслуживания.
- Просмотр списка задач.
- Фильтрация задач по статусу.
- Поиск по оборудованию и описанию.
- Перевод задачи в работу.
- Закрытие выполненной задачи.
- Получение списка задач через JSON API.

### Нефункциональные требования
- Проект должен работать локально на учебном компьютере.
- Интерфейс должен быть удобным для просмотра задач.
- Хранение данных должно выполняться в SQLite.
- Структура проекта должна быть разделена на сервер, клиент и базу данных.

### Технологический стек
| Технология | Назначение |
|---|---|
| Python | Основной язык приложения. |
| Flask | Маршруты и HTML-рендеринг. |
| SQLite | Хранение оборудования и задач. |
| HTML | Структура интерфейса. |
| CSS | Оформление интерфейса и карточек задач. |

### Макет интерфейса
Интерфейс содержит статистику, форму добавления оборудования, форму создания задачи обслуживания, фильтр и список карточек задач.

### Предварительное описание API
| Метод и путь | Параметры | Назначение | Ответ |
|---|---|---|---|
| `GET /` | status, search | Открывает главную страницу. | HTML. |
| `POST /equipment` | inventory_number, name, equipment_type, location, responsible | Добавляет оборудование. | Redirect. |
| `POST /tasks` | equipment_id, task_type, planned_date, priority, description | Создаёт задачу обслуживания. | Redirect. |
| `POST /tasks/<id>/start` | id в URL | Переводит задачу в работу. | Redirect. |
| `POST /tasks/<id>/complete` | id в URL | Завершает задачу. | Redirect. |
| `GET /api/tasks` | status, search | Отдаёт список задач. | JSON. |

### Модель данных
```text
equipment (1) -> (many) maintenance_tasks
```
