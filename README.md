# 📋 Планировщик обслуживания электрооборудования

Веб-приложение для планирования осмотров, ремонтов и профилактики
электрооборудования. Позволяет вести карточки оборудования, создавать
задачи обслуживания, отслеживать их статус и фильтровать по приоритету
или поисковой строке.

## 🎯 Цель разработки

Разработать концепцию и техническое задание для веб-приложения
«Планировщик обслуживания электрооборудования».

## 📁 Структура репозитория

- `app.py` — Flask-маршруты: главная, оборудование, задачи, JSON API.
- `database.py` — работа с SQLite и демо-данные.
- `schema.sql` — SQL-схема таблиц.
- `maintenance.db` — база SQLite (создаётся автоматически).
- `requirements.txt` — список зависимостей.
- `templates/index.html` — HTML-шаблон интерфейса.
- `static/styles.css` — оформление.

## 1. АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ

### 1.1 Описание предметной области

На производстве оборудование требует планового обслуживания. Если
работы вести без единой системы, сложно контролировать сроки,
приоритеты и ответственных. Приложение позволяет свести эти данные
в один интерфейс.

**Проблемы текущей ситуации:**
- Отсутствие единой системы учёта оборудования.
- Пропуск плановых осмотров и ремонтов.
- Сложно увидеть, кто отвечает за конкретный объект.
- Данные хранятся в разных файлах.

### 1.2 Целевая аудитория

| Роль | Потребности |
|------|-------------|
| **Техник** | Создавать задачи обслуживания |
| **Инженер** | Контролировать статус выполнения |
| **Ответственный по участку** | Добавлять оборудование и вести карточки |

### 1.3 Решаемые задачи

- Автоматизация учёта оборудования и задач обслуживания.
- Визуализация статусов работ.
- Фильтрация задач по статусу и поиск по описанию.
- Получение списка задач через JSON API.

## 4. МОДЕЛЬ ДАННЫХ

### 4.1 ER-диаграмма

```
┌─────────────────┐       ┌──────────────────────┐
│    equipment    │       │  maintenance_tasks   │
├─────────────────┤       ├──────────────────────┤
│ id (PK)         │◄──────┤ equipment_id (FK)    │
│ inventory_number│       │ id (PK)              │
│ name            │       │ task_type            │
│ equipment_type  │       │ planned_date         │
│ location        │       │ priority             │
│ responsible     │       │ description          │
│ status          │       │ status               │
│                 │       │ completed_at         │
└─────────────────┘       └──────────────────────┘
```

Связь: одна единица оборудования может иметь много задач
(`equipment → maintenance_tasks`, один ко многим).

### 4.2 Описание таблиц

**Таблица equipment**
| Поле | Тип | Описание |
|------|-----|----------|
| id | INTEGER | Первичный ключ |
| inventory_number | TEXT | Уникальный номер |
| name | TEXT | Название |
| equipment_type | TEXT | Тип |
| location | TEXT | Место установки |
| responsible | TEXT | Ответственный |
| status | TEXT | active / service / stopped |

**Таблица maintenance_tasks**
| Поле | Тип | Описание |
|------|-----|----------|
| id | INTEGER | Первичный ключ |
| equipment_id | INTEGER | Внешний ключ на equipment.id |
| task_type | TEXT | Тип работ |
| planned_date | TEXT | Плановая дата |
| priority | TEXT | low / normal / high |
| description | TEXT | Описание |
| status | TEXT | planned / in_progress / done |
| completed_at | TEXT | Дата завершения |

## 5. ПРОЕКТИРОВАНИЕ API

| Метод | URL | Назначение | Ответ |
|-------|-----|-----------|-------|
| GET | `/` | Главная страница (`?status`, `?search`) | HTML |
| POST | `/equipment` | Добавление оборудования | Redirect |
| POST | `/tasks` | Создание задачи | Redirect |
| POST | `/tasks/<id>/start` | Перевод в работу | Redirect |
| POST | `/tasks/<id>/complete` | Завершение задачи | Redirect |
| GET | `/api/tasks` | JSON-список задач (`?status`, `?search`) | JSON |

### Пример JSON-ответа

```json
{
  "count": 2,
  "items": [
    {
      "inventory_number": "EQ-001",
      "name": "Трансформатор ТМ-250",
      "task_type": "Плановый осмотр",
      "status": "planned"
    }
  ]
}
```

## 6. КЛИЕНТСКАЯ ЧАСТЬ

- `templates/index.html` — HTML-шаблон: шапка, формы, фильтр, карточки задач.
- `static/styles.css` — оформление карточек, форм, статистики, кнопок.

**Основные кнопки:**

| Кнопка | Действие |
|--------|----------|
| Добавить | Сохраняет оборудование |
| Создать задачу | Добавляет обслуживание |
| Показать | Применяет фильтр |
| Начать | Меняет статус на `in_progress` |
| Выполнено | Меняет статус на `done` |
